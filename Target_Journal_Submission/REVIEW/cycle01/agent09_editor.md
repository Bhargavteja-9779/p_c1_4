# Reviewer 9 – Associate Editor, *Sleep Medicine* (cycle 1)

Checked against the rebuilt files (16 Nov 18:35; PDF A4, 30 pp.). All counts are my own.

## Summary of the submission (3-5 sentences)
The authors turn a stager's epoch probabilities into per-night 90% intervals for eight PSG parameters, using temperature recalibration, an FFBS-sampled HMM posterior and normalised split-conformal calibration. They test it with YASA and an in-domain LightGBM on Sleep-EDF SC/ST and HMC (348 nights). Within-cohort coverage is nominal; gains over bias-corrected limits of agreement are parameter-specific (9 better, 4 worse of 24); coverage fails across cohorts and is restored by local calibration. The topic is in scope and clinically relevant, but the package fails the technical check, a key clinical recommendation is partly unsupported, and it reads as a methods paper.

**Compliance check (current files).** Abstract 288 words, structured ✓; highlights 5, 85/82/80/79/80 characters ✓ (H1 at the limit); main text 4,230 (mine) / 4,449 (declared) ✓; display items 3 + 5 = 8, at the limit; 41 references in square brackets ✓; 6 keywords ✓; required sections ✓; declarations incomplete (M2, M3); figure order non-compliant (Mi1).

## Fatal concerns
**F1. Table 2 (the primary results table) is corrupted in both submission files, and the rebuild did not fix it.** `tables/table2_display.md` uses `|` inside cells. Pandoc keeps 5 cells per row: DOCX rows read `['YASA','TST (min)','0.907','85.3','0.85*']`, and so does the PDF (pp. 25–26). The "ST" column shows the SC width, "HMC" shows the SC ratio, and all ST/HMC results are missing. Text values attributed to Table 2 (TST ratios 0.59/0.71) cannot be checked. *Action:* rebuild Table 2 with one sub-column per statistic and cohort, or split it into a coverage/width table and a ratio table. If the split pushes the paper past 8 display items, move Fig. 2 to the Supplement (Mo3).

## Critical/Major concerns
**M1 (critical). The claim that "a few locally scored nights" correct the TST bias is not supported.** Table 3's calibrated plug-in uses the `xfit` configuration, in which temperature scaling is fitted on the other 4 folds of the same cohort (`code/experiments/e03_night_summaries.py` l.4–5). That is about 121 HMC nights and about 35 ST nights. The few-night experiment (`e06_cross_cohort.py`) reads `*_srcSC.csv`, so stage probabilities were never recalibrated on target nights; only the conformal step was. With SC-fitted recalibration, the HMC TST bias of the calibrated plug-in is still **−20.3 min (MAE 26.0)**, against −4.8 within-cohort (my computation from `results/summaries/yasa_srcSC.csv`). Affected: Discussion ¶1 ("on a few locally scored nights"), Conclusion, abstract Conclusions, Highlight 4, cover-letter bullet 3. *Action:* run the experiment (recalibrate on n_t ∈ {10, 20, 30, 50} target nights and report TST bias and MAE), or reword to "≈120 cross-fitted local nights".

**M2 (critical). Placeholders and unconfirmed declarations stop submission.** Manuscript: `[AUTHOR NAME(S)]` ×2, affiliation, corresponding author, CRediT, and four `[AUTHOR ACTION REQUIRED]` notes (GenAI, competing interests, funding, repository DOI). Cover letter: date, confirmation paragraph, suggested reviewers, signature block; the source still has `{{nights_total}}`. *Action:* complete all of these, and deposit the code with a DOI before submission.

**M3 (major). Generative-AI policy compliance is a desk-rejection risk.** The declaration says Claude was used to "design and implement the analysis code, run the experiments and draft the manuscript text". I checked Elsevier's current policy page (elsevier.com, "Generative AI policies for journals", 16 Nov 2026). It says AI "must not replace your own scientific judgement, analysis, interpretation". It also says AI used in research methods should be "described … in the Methods section", and it titles the declaration "…in the manuscript preparation process". Methods §2.9 does not mention AI. *Action:* describe the AI's role in §2.9 (tool and version, tasks, how humans verified the work); state which design and interpretation decisions the authors made; use the current section title.

**M4 (major). The clinical usefulness of the interval widths is never shown.** Table 2 widths for YASA: TST 85–88 min (SC/HMC), WASO 231 min (SC), REM latency 95–184 min, and N3% 30 pp on HMC, where mean N3 is 19.5%. With ten local HMC nights the widths are larger: TST 129 min, REM latency 187 min, N3% 35.6 pp (`tables/tableS_fewshot.csv`). The proposed intervals are narrower than distribution-free LoA in only **13/24 (YASA) and 14/24 (LightGBM)** combinations (`tableS_all_methods_within.csv`, α = 0.10). In Fig. 1f the REM-latency interval spans 0–140 min. The abstract reports no width; the threshold flagging proposed in the Discussion (TST 6 h, REM latency 15 min) is never tested. *Action:* give widths in clinical units in the abstract. Report the share of nights whose interval straddles TST 360 min, sleep efficiency (SE) 85% and REM latency 15 min, and the sensitivity, specificity and review workload for catching plug-in misclassification at these thresholds. Relate widths to inter-scorer variability.

**M5 (major). The "ten nights restored coverage" result is a known property of split conformal, and the site-level risk is understated.** With n = 10 and α = 0.10, the conformal quantile is the largest calibration score, so expected coverage is 10/11 = 0.909. That matches the reported 91.0%, and the values for 20/30/50 nights (0.905/0.903/0.902) match Fig. 4b in the same way. Coverage at a single site then follows a Beta(10,1) distribution, so P(<0.80) = 0.8¹⁰ = 0.107, which is the reported "11%" (§3.5). Highlight 5 and the Clinical-use paragraph nonetheless present ten nights as sufficient. *Action:* present these values as theory confirmed by the data. Derive the recommended number of nights from a risk target, e.g. P(coverage < 0.85) ≤ 5%, and report the width cost of each number of nights in the main text.

**M6 (major). The paper is too methodological for this readership, and it does not say which number a clinician should report.** Methods: 1,287 words, five equations plus FFBS recursions; the §3.3 ablation paragraph is ~330 words; the abstract and highlights rely on "interval score", "cohort–parameter combinations" and "posterior-spread scaling at a fixed centre". The pre-specified method centres on the posterior mean, which Table 3 shows is worse than the calibrated plug-in for WASO-SC (bias +68.2 min), REM% and SOL. The variant the Discussion recommends (calibrated plug-in centre with posterior scale) is exploratory. *Action:* recommend one clinical procedure and state its point estimate. Move equations (2)–(3), the recursions, the ablations, the factorial design, CQR, Mondrian calibration and independent sampling to the Supplement. Add a schematic and a "how to read a per-night interval" box, and rewrite Highlights 2–3 in clinical terms.

## Moderate concerns
**Mo1. The cohorts and parameters are a weak base for clinical claims.** 197/348 nights are 1989–94 Sleep-EDF (R&K, Fpz-Cz); HMC has no demographics or diagnoses; Table 1 lacks reference parameters, AHI and diagnoses; SE is not analysed although the cover letter cites it; the 10-h SC window creates the WASO artefact (231-min intervals; §3.6). *Action:* base the clinical claims on HMC, add SE, add reference parameters to Table 1, and flag or drop SC WASO. If feasible, add a modern multi-scorer cohort.

**Mo2. The title and abstract overstate and use jargon.** "With external validation" overstates what was shown: SC-calibrated coverage fell to 38% for N3% on HMC. In the Results, "restored it to 91%" leaves unclear what "it" refers to, and the number of recalibration nights is not given. *Action:* use a clinical title (e.g. "How wrong can an automatically scored sleep parameter be tonight? Per-night intervals for automatic PSG scoring"), and add widths and night counts to the abstract.

**Mo3. The display items need rebalancing.** Figs. 2 (six methods × 48 dots, no CIs) and 5 are methods figures. Fig. 5/§3.7 silently report **unweighted means over cohorts**: TST coverage 0.32 = mean(0.619, 0.204, 0.147); width 71→108 min likewise (`tableS_robustness.csv`). *Action:* move Figs. 2 and 5 to the Supplement, report robustness per cohort, and use the freed slots for the threshold/workload analysis and a readable Table 2.

**Mo4. The flagging results have no clinical operating point.** AUROCs are mostly 0.6–0.8. For ST TST, entropy and maximum probability (0.84) beat interval width (0.80) (Fig. 3d). *Action:* report sensitivity at a fixed review budget, e.g. 20% of nights.

## Minor concerns
**Mi1.** Figures are first cited in the order 1, 2, 4, 5, 3 (Fig. 3 first appears in §3.8). Renumber them.
**Mi2.** Fig. 4d's y-axis starts at 0.3, which silently drops the LightGBM/HMC N3% points for BA-LoA (0.278) and CQR-FFBS (0.291) (`tableS_cross_cohort_source_only.csv`). Panels b/c/e/f use narrow y-ranges that exaggerate small differences and show no site-level spread.
**Mi3.** In Fig. 1e, the legend overlaps the plug-in line and the reference line.
**Mi4.** Table 3 prints p = "0.000" and "1.000" and does not say whether these are adjusted for multiplicity. Table 1 lacks thousands separators and counts "Female nights" rather than female subjects.
**Mi5.** The ratio convention flips: Table 2 uses "<1 favours proposed", while §3.3/S4 uses ">1 favours the pre-specified method".
**Mi6.** References: [18] reads "Sleep 2022;46" (volume 46 is 2023); [28] reads "Aeilko Zwinderman"; [41] lacks pages e215–e220; check author "NT H" in [6]; [8] is about AHI scoring but is cited as a validation of sleep-parameter agreement (Intro ¶1). Every PDF page number is printed twice.

## Required additional experiments/analyses
1. Recalibrate stage probabilities with n_t local nights and report TST bias/MAE against n_t (M1).
2. Threshold-straddling analysis with review workload, sensitivity and specificity for TST 6 h, SE 85% and REM latency 15 min, using the existing summaries (M4, Mo4).
3. A risk-based recommended number of calibration nights, with widths at each number, in the main text (M5).
4. Add SE as a parameter (Mo1); report robustness per cohort (Mo3).

## Recommendation
**Major revision: return to authors before external review.** The scope fits and the question matters clinically. But the submission fails the technical check (F1, M2), puts the journal's AI-policy compliance in doubt (M3), and states its central clinical recommendation about bias correction more strongly than the evidence allows (M1). Resubmitted without clinical reframing (M4–M6), it would likely be desk-rejected as better suited to a methods journal.
